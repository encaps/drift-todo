# Drift for macOS

A thin Tauri v2 shell around the deployed Drift web app. It loads the production
URL in a WKWebView, so there is no second copy of the frontend and no separate
deploy: whatever is live is what the app shows.

## What the shell adds

- **Global hotkey** — `Cmd+Shift+Space` from any app shows Drift and opens quick
  add. It replays the `n` keydown the web app already listens for, so there is
  no web-side change.
- **Menu-bar icon** — Show Drift, Quick Add, Launch at Login, Quit.
- **Launch at login** — toggled from the menu-bar menu; installs a LaunchAgent.

## Setup

```bash
npm install          # Tauri CLI
npm run dev          # run against the URL in src-tauri/tauri.conf.json
npm run build        # Drift.app in src-tauri/target/release/bundle/macos/
```

Rust is required (`curl https://sh.rustup.rs -sSf | sh`).

## The app URL

One place: `app.windows[0].url` in `src-tauri/tauri.conf.json`. Point it at
`http://localhost:3000` to develop against the local Next.js dev server, or at
the production URL for a real build.

## Icons

`npm run icons` regenerates the Dock/DMG icons from `../public/icon-512.png`.
The menu-bar icon is separate: `src-tauri/icons/tray.png` (and `@2x`) is a bare
"d" glyph on a transparent background, because macOS template images use only
the alpha channel and would render the square app icon as a solid blob. It is
generated by `scripts/tray-icon.swift`.

## Known limits

- **Web push does not work in the shell.** WKWebView outside Safari has no Push
  API, so the "enable notifications" banner is a no-op here. The daily reminder
  still reaches Safari and the iPhone home-screen install.
- **Closing the window quits the app**, which also drops the menu-bar icon and
  the global hotkey. To keep it resident instead, prevent the close in
  `src/main.rs` with an `on_window_event` handler that calls `window.hide()`.
- The build is unsigned. macOS will warn on first open unless you sign it
  (`bundle.macOS.signingIdentity`) or right-click → Open once.
- **`bundle.targets` is `["app"]`, not `dmg`.** The DMG bundler shells out to
  `bundle_dmg.sh`, which tells Finder to lay out the disk-image window over
  AppleScript. That needs Automation → Finder permission for whatever launched
  the build, and it fails with a bare `failed to run bundle_dmg.sh` without it.
  To ship a DMG, grant that permission (System Settings → Privacy & Security →
  Automation) and add `"dmg"` back to the targets list.
